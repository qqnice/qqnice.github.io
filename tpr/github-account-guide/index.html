核心觀念 1

電子郵件驗證 ≠ 2FA

申請一般個人帳號必須完成註冊表單與電子郵件驗證（否則無法建立儲存庫）。GitHub 官方明確說明：信箱驗證不能充當兩階段驗證（2FA）的第二因素。

核心觀念 2

2FA 是否強制？建議當天啟用

GitHub 沒有要求每位新用戶在註冊當下全面強制開啟 2FA；但對被選入的程式碼貢獻者強制要求（45 天設定期＋7 天寬限期），學校或課程組織也可要求成員開啟。

核心觀念 3

註冊方式：Email＋密碼為主

本教學以最通用的「電子郵件＋密碼」逐步示範。GitHub 註冊頁上方也提供 Continue with Google 與 Continue with Apple 社群登入選項；學校配發之 EMU 帳號則請依管理員指示登入。

核心觀念 4

四不外洩原則（資安底線）

密碼、Email 驗證碼、2FA QR code / setup key、復原碼（Recovery codes）絕對不可截圖公開、投影給全班或交給老師與同學。

手冊第二部分 · 官方政策核對

目前每位新用戶註冊當下都被全面強制啟用 2FA 嗎？

1. 新用戶註冊當下：非全面強制，但強烈建議當天啟用

GitHub 並未要求每位新用戶在註冊完成當下都強制開啟 2FA。剛註冊一般個人帳號時，必須先完成的是「電子郵件驗證」。但為保護個人專案與作業安全，建議在申請當天就完成驗證器 App 與復原碼設定。

關鍵區別：不要把「已驗證電子郵件」當作「已完成 2FA」！
GitHub 官方明確說明：電子郵件登入驗證（Email verification）不能充當兩階段驗證的第二因素。

2. 哪些人會被強制要求開啟 2FA？

  • 被選入強制 2FA 計畫的程式碼貢獻者：自 2023 年 3 月起，GitHub 分批要求在 GitHub.com 貢獻程式碼的個人帳號啟用至少一種 2FA。被選中者會收到 Email 與網站頂部橫幅通知。
  • 45 天設定期＋7 天寬限期：收到強制通知後有 45 天設定期，到期後還有 7 天寬限期；若逾期仍未啟用，將無法存取 GitHub.com 直到完成設定。
  • 學校課程或專案組織（Organization）要求：許多學校課程組織或開源團隊會要求成員必須開啟 2FA 才能存取私有儲存庫。
  • 28 天檢查期（Check up period）：開啟 2FA 後會進入 28 天檢查期；期間內成功完成一次 2FA 登入即可通過，否則第 28 天會在既有登入工作階段提示驗證。

手冊第三部分 · 驗證器 App 準備

下載與安裝 TOTP 驗證器 App（以 Google Authenticator 為例）

GitHub 建議以 TOTP（Time-based One-Time Password）驗證器 App 作為主要 2FA 方法（比簡訊 SMS 更可靠且不受跨國簡訊延遲影響），並建議後續再加設通行密鑰（Passkey）或安全金鑰（Security Key）作備用。TOTP App 會每 30 秒產生一組六位數代碼，不限特定品牌；若已安裝 1Password、Authy、Microsoft Authenticator 等相容 RFC 6238 的 App 可直接沿用。

重要應變指南

換手機、重置手機或遺失驗證器裝置時怎麼辦？

許多學生在換新手機或手機送修時，才發現無法產生 6 位數驗證碼。請依您目前的情況查看標準處理流程：

情境 A：準備換新手機（舊手機還能使用）

  1. 轉移驗證器帳戶：先在舊手機的 Google Authenticator 使用「轉移帳戶 / 匯出」功能，或確認雲端同步已開啟並在換機後成功顯示 GitHub 六位數代碼。
  2. 或在 GitHub 重新設定 TOTP：登入 GitHub → Settings → Password and authentication → 在 Authenticator app 旁按 Edit，直接用新手機重新掃描 QR code（無須先停用整個 2FA，可保留既有復原碼與組織成員資格）。
  3. 切勿先格式化舊手機：務必確認新手機已能正常通過 GitHub 登入驗證後，再清除舊手機資料。

情境 B：手機已遺失／故障，但保有 Recovery codes 或備用方法

  1. 使用復原碼登入：在 GitHub 登入要求輸入 2FA 驗證碼的畫面，點選 More options → Use a recovery code（或 2FA recovery code），輸入當初下載保存的其中一組 10 字元復原碼（每組只能用一次）。
  2. 或使用備用驗證方式：若有設定 Passkey（通行密鑰）、Security key（安全金鑰）或 GitHub Mobile，可直接選擇該備用方法登入。
  3. 登入後立即重綁新裝置：進入 Settings > Password and authentication 重新綁定新的驗證器 App，並重新檢查剩餘復原碼數量（必要時產生新的一組復原碼並安全保存）。

情境 C：手機遺失，且復原碼與所有備用方法都找不到

  1. 檢查是否有已驗證裝置或金鑰：若您曾在常用的電腦瀏覽器保留 _device_id cookie（已驗證裝置）、或電腦中留有有效的 SSH key / Personal Access Token (PAT)，可依官方指南嘗試發起帳號復原請求。
  2. 官方警語：若所有第二因素與復原碼皆遺失，且無已驗證裝置或金鑰，GitHub Support 也無法為您繞過 2FA，帳號可能永久無法取回。這正是為什麼步驟 7 下載並異地保存復原碼至關重要！

教師課堂驗收建議

如何安全驗收學生的 GitHub 帳號與 2FA 狀態？

在課堂或作業繳交時，請遵循「只驗公開帳號與啟用狀態、不收機敏憑證」的原則：

  • 建議展示畫面 1（確認帳號與 Username）： 請學生展示「已登入自己的 GitHub 個人頁（https://github.com/學生Username）」或提交公開個人頁網址。
  • 建議展示畫面 2（確認 2FA 已啟用）： 請學生打開 Settings → Password and authentication，展示畫面中 Authenticator app 旁顯示綠色的 Enabled 狀態標籤。
  • 絕對禁止蒐集或拍攝的項目： 不要蒐集、拍攝或要求學生提交密碼、電子郵件驗證碼、2FA QR code、setup key、六位數動態驗證碼或復原碼（Recovery codes）。
  • 截圖遮蔽提醒： 若課堂作業需要學生繳交設定頁截圖，請提醒學生先將畫面中的個人電子郵件地址或電話號碼塗黑遮蔽。
