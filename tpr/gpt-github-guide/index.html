GPT × GitHub
一句提示詞，把網頁發佈出去

先完成一次 GitHub 連接與權限檢查，再填入網站主題、儲存庫與發佈路徑，產生能直接貼給 GPT 的提示詞。最後依提交紀錄與公開頁面驗收。

首次連接：照順序完成 5 步

以下以 ChatGPT／Codex 目前的插件流程為例。選單名稱、可用插件和可執行動作會因帳號、方案、管理員設定與版本而異。登入與授權畫面須由 GitHub 帳號持有人完成。

先知道：「只下一句 Prompt」無法跳過第一次登入、GitHub 授權或儲存庫權限設定。插件若只有讀取權限，提示詞也無法替它取得寫入權限；先完成連接與能力檢查，再要求發佈。

04 · VERIFY公開驗收檢查 commit、Actions、網址
0 / 5 步已完成
1

準備 GitHub 帳號與目標儲存庫

先登入自己的 GitHub，確認可編輯目標儲存庫。此範例使用 qqnice/qqnice.github.io，教學頁放在 tpr/ 下；使用其他帳號時，請改成自己的儲存庫。

2

在 ChatGPT 或 Codex 安裝 GitHub 插件

  1. 開啟 Plugins 目錄 ↗（或桌面 App 的 Plugins 分頁）。
  2. 搜尋 GitHub，打開插件說明，確認它能提供哪些讀取或寫入動作，再按加入／安裝。
  3. 若畫面顯示 Connect，依指示連接 GitHub；有的插件在首次使用時才要求連接。安裝後請開啟新對話。

OpenAI 官方流程：Plugins 分頁 → 搜尋插件 → 安裝 → 視需要連接 → 開新對話。

3

登入 GitHub 並審核授權

在 GitHub 官方授權畫面登入正確帳號，仔細檢查要開放的儲存庫與權限。若跳出 GitHub 兩階段驗證，可依原本的 Google Authenticator 教學完成。組織儲存庫可能還需要管理員允許。

請勿把密碼、個人存取權杖、驗證碼或復原碼貼進聊天訊息或本網站。

4

開新對話，先做唯讀測試

在 ChatGPT Work 或 Codex 開新對話。可直接說明工作，或在輸入框輸入 @ 選擇已安裝的 GitHub 插件。先複製下方「連接測試」Prompt，確認 GPT 能辨識正確儲存庫、預設分支，以及連線是否真的具備寫入動作。

5

確認 GitHub Pages 的發佈來源

到目標儲存庫的 Settings → Pages 看 Build and deployment。若尚未設定，選 Deploy from a branch，再指定分支與來源資料夾（根目錄 / 或 /docs）。若原本網址已在運作，保留原設定並在現有網站目錄新增子頁。

本範例可直接核對 qqnice 儲存庫的 Pages 設定 ↗；其他人請換成自己的儲存庫網址。

填入資料，產生自己的發佈提示詞

先用 Prompt 1 確認連線，再填下方五項資訊。本工具只在你的瀏覽器組合文字，不上傳表單內容，也不會代你登入 GitHub。

請將手冊附在真正的 GPT 對話中；不要在這裡或 Prompt 中填入密碼、Token、2FA 代碼、復原碼或學生個資。

收到「完成了」之後，逐項驗收

文字回覆不是部署證據。至少要能找到提交、部署結果與實際公開頁面。

1. 看提交紀錄

請 GPT 提供 commit 連結與 SHA。開啟後確認儲存庫、分支、檔案路徑及修改範圍正確，沒有把無關檔案一起公開。查看本範例提交 ↗

2. 看 Pages 部署

查看 Actions 的 pages build and deployment 是否顯示成功。發佈可能需要數分鐘，GitHub 文件說明最長可到約 10 分鐘。查看本範例 Actions ↗

3. 開公開網址實測

從首頁點進新頁，試用導覽、進度勾選、複製按鈕、手機版和官方來源連結。若有 PDF 或圖片也要逐一打開。查看本範例首頁 ↗

4. 檢查公開內容

GitHub Pages 可供網路上的人開啟。檢查檔案、圖片、文件和程式碼，確認沒有密碼、權杖、學生個資或不應公開的素材。

完成判定：能提供正確的 commit、Pages 部署成功，且公開網址實際載入新版並可操作，才算真正發佈完成。若任一步失敗，請把錯誤訊息與對應連結貼回同一段 GPT 對話，要求修正後重新驗收。

連接或發佈卡住時

找不到 GitHub 插件或 Connect 按鈕？

先確認目前使用的是支援插件的 ChatGPT／Codex 介面，重新開一個對話；可用功能仍取決於方案與工作區管理設定。從 Plugins 目錄檢查是否已安裝。若組織停用插件，需由管理員處理。

GPT 看不到指定儲存庫？

核對登入的 GitHub 帳號、儲存庫名稱、是否是私人庫，以及插件被授權的儲存庫範圍。組織儲存庫可能需要額外批准。先做 Prompt 1 的唯讀測試，不要直接要求發佈。

只能讀取，不能建立檔案或推送？

提示詞無法超越連線的權限。改用具寫入能力的連線或具有 Git 推送權限的 Codex 專案；也可以讓 GPT 先產生檔案或 PR，再由有權限的人完成發佈。不要把個人存取權杖貼進聊天訊息。

GPT 說已發佈，但網址仍是舊版？

檢查它是否真的建立了 commit、Pages 是否指向該分支與資料夾，並查看 GitHub Actions 的 Pages 部署結果。稍候重新整理公開網址；若仍失敗，請 GPT 根據實際部署錯誤修正，勿只接受文字宣稱。

連接後又要求 GitHub 兩階段驗證？

在 GitHub 官方頁面完成驗證即可。使用原本設定的 Google Authenticator 或復原方法；驗證碼只輸入 GitHub 頁面，不要貼給 GPT。查看 GitHub 帳號與 2FA 教學。

可以直接把私人儲存庫、學生資料或 Token 貼給 GPT 嗎？

先確認插件的授權範圍和資料使用情境；網站及提示詞不要包含密碼、Token、復原碼或學生個資。若教材原本是私人資料，先整理成可公開版本再發佈。
