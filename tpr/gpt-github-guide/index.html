GPT × GitHub
一句提示詞，把網頁發佈出去

先完成一次 GitHub 連接與權限檢查。之後說明目標、儲存庫、檔案位置和驗收條件，讓 ChatGPT Work 或 Codex 協助製作、提交並檢查網站。

完整流程只有四段
  1. 安裝並連接 GitHub 插件
  2. 確認儲存庫與寫入權限
  3. 貼上清楚的發佈提示詞
  4. 核對提交與公開網址

首次連接：照順序完成 5 步

以下以 ChatGPT／Codex 目前的插件流程為例。選單名稱、可用插件和可執行動作會因帳號、方案、管理員設定與版本而異。登入與授權畫面須由 GitHub 帳號持有人完成。

先知道：「只下一句 Prompt」無法跳過第一次登入、GitHub 授權或儲存庫權限設定。連接完成後，才適合把製作與發佈工作交給 GPT 執行。
0 / 5 步已完成
1

準備 GitHub 帳號與目標儲存庫

先登入自己的 GitHub，確認可編輯目標儲存庫。此範例使用 qqnice/qqnice.github.io，教學頁放在 tpr/ 下；使用其他帳號時，請改成自己的儲存庫。

2

在 ChatGPT 或 Codex 安裝 GitHub 插件

  1. 開啟 Plugins 目錄 ↗（或桌面 App 的 Plugins 分頁）。
  2. 搜尋 GitHub，查看插件提供的讀取、寫入和發佈動作，然後安裝。
  3. 若畫面顯示 Connect，依指示連接 GitHub；有的插件在首次使用時才要求連接。
3

登入 GitHub 並審核授權

在 GitHub 官方授權畫面登入正確帳號，檢查可存取的儲存庫及權限範圍。若儲存庫屬於學校或組織，可能還需要管理員允許。請勿把密碼、個人存取權杖或 2FA 驗證碼貼進聊天訊息。

4

開新對話，先做唯讀測試

在 ChatGPT Work 或 Codex 開新對話。可直接說明工作，或在輸入框輸入 @ 選擇 GitHub 插件。先複製下方「連接測試」Prompt，確認 GPT 能辨識正確儲存庫、預設分支，以及它具備哪些寫入動作。

跳到連接測試 Prompt ↓

5

確認 GitHub Pages 的發佈來源

到目標儲存庫的 Settings → Pages 看 Build and deployment。若尚未設定，選 Deploy from a branch，再指定分支與來源資料夾（通常為根目錄或 /docs）。若原本網址已在運作，保留原設定並在現有網站目錄新增子頁。

直接複製：從測試連接到發佈

提示詞要寫出目標、來源資料、儲存庫與路徑、保留哪些現有內容，以及如何驗收。把方括號中的文字換成自己的資訊。

Prompt 1｜唯讀確認連接
Prompt 2｜讓 GPT 建站、提交、發佈並驗收
Prompt 3｜後續更新已發佈網站
實際案例：本專區使用的儲存庫是 qqnice/qqnice.github.io，公開首頁是 https://qqnice.github.io/tpr/。若要保留首頁，把新教學放在 tpr/新主題/，再新增入口卡片即可。

收到「完成了」之後，要看這 4 件事

1. 看提交

開啟 GPT 提供的 commit 或 PR，確認儲存庫、分支、檔案路徑正確，也沒有把無關檔案一起公開。

2. 看 Pages 網址

點開公開網址，確認有新頁面。GitHub 官方說明指出，推送後網站更新可能需要數分鐘，最長可到約 10 分鐘。

3. 點互動

試用導覽按鈕、進度勾選、手機版版面和外部官方連結。只有檔案上傳成功，不等於網頁功能都能用。

4. 看是否公開了敏感內容

GitHub Pages 網站可在網路上公開存取。上傳前檢查資料、圖片、文件與程式碼，避免包含密碼、權杖、學生個資和未取得同意的素材。

連接或發佈卡住時

找不到 GitHub 插件或 Connect 按鈕？

先確認目前使用的是支援插件的 ChatGPT／Codex 介面，重新開一個對話；可用功能仍取決於方案與工作區管理設定。從 Plugins 目錄檢查是否已安裝。若組織停用插件，需由管理員處理。

GPT 看不到指定儲存庫？

核對登入的 GitHub 帳號、儲存庫名稱、是否是私人庫，以及插件被授權的儲存庫範圍。組織儲存庫可能需要額外批准。先做 Prompt 1 的唯讀測試，不要直接要求發佈。

只能讀取，不能建立檔案或推送？

提示詞無法超越連線的權限。改用具寫入能力的連線或具有 Git 推送權限的 Codex 專案；也可以讓 GPT 先產生檔案或 PR，再由有權限的人完成發佈。不要把個人存取權杖貼進聊天訊息。

GPT 說已發佈，但網址仍是舊版？

檢查它是否真的建立了 commit、Pages 是否指向該分支與資料夾，並查看 GitHub Actions 的 Pages 部署結果。稍候重新整理公開網址；若仍失敗，請 GPT 根據實際部署錯誤修正，勿只接受文字宣稱。
