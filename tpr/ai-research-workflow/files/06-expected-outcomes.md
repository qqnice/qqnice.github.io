# 預期完成工作項目與成果

本計畫預期完成的成果不只包含課程教材與期末作品，也包含能辨識學生真實學習的任務、評量規準、歷程證據與公開分享資源。所有成果將圍繞「生成式 AI 開放情境下的 PAVET 真實學習證據鏈」，並以 Linux 容器化服務部署、監控與災難復原作為技術實作主軸。

## （2）預期達成之與學生學習相關之目標

### 一、學習效益指標

下列門檻為申請階段的**暫定成功標準**。可在前導試作後依題目難度與實驗環境合理調整，但須於正式資料蒐集前完成預先確定並保留修訂理由；研究開始後不因結果高低而移動門檻。

四級分析規準暫定為：第1級「尚無法完成或缺乏證據」、第2級「能依提示完成部分步驟」、第3級「能獨立完成並以適當證據說明」、第4級「能處理變式、比較方案並提出限制或改善」。

### 二、成果判讀原則

1. **不以作品完成率單獨代表學習。**容器服務成功啟動只能證明人機系統完成任務，仍須配合AI暫停變式、延宕保留、微口試及證據品質判斷學生能力。
2. **不以滿意度取代學習成效。**學生接受度與認知負荷只用來判斷可行性，不作為PAVET有效的主要證據。
3. **同時呈現達標率與變化量。**除了平均數，亦報告達到規準第3級的學生比例、個別變化、效果量及信賴區間。
4. **如實呈現未達預期之結果。**若部分指標未達門檻，將分析是介入理論、任務難度、實施忠實度、技術環境或學生先備差異所致，不將無顯著差異解讀為完全無效，也不選擇性報告正面結果。

## （4）教學成果對教學社群可能產生之影響與貢獻

### 一、對課程與評量實務的貢獻

1. **由AI使用管制轉向能力證據設計。**本計畫不以禁止或偵測AI為核心，而是示範如何透過預判、驗證、解釋及遷移，取得較能歸因於學生的學習證據。
2. **提供技術實作課程可直接改編的工具組。**PAVET表單、故障注入方法、驗收腳本、微口試題型及四級規準，可供Linux、雲端、網路、程式設計、資安與系統管理課程調整使用。
3. **建立「AI在場表現」與「學生真實學習」的區辨方式。**同時測量成品、AI暫停變式、延宕保留與歷程行為，可降低只用期末作品推論學習的風險。
4. **提供兼顧工作真實性與評量效度的折衷模式。**主要任務允許AI，只有在短時證據窗口暫停AI，既保留職場工具使用，也能檢核學生自己的診斷與遷移能力。
5. **形成可持續改進的課程資料。**以介入忠實度、學生歷程、反例與教師札記記錄有效條件及失敗原因，讓後續教師能依證據修改，而非只複製活動名稱。

### 二、對教學社群的擴散機制

| 擴散機制 | 預期行動 | 可檢核成果 |
|---|---|---|
| 校內共同備課 | 邀請相關領域教師檢視任務與規準 | 至少3名教師或助教提供結構化回饋，形成修訂紀錄 |
| 教師試用 | 邀請至少1門相關課程試用一份PAVET表單、故障任務或微口試規準 | 蒐集適用性、時間負荷及修改建議；不將試用直接宣稱為成效驗證 |
| 公開資源維護 | 建立版本化資源庫及問題回報方式 | 發布第1版資源包、變更紀錄與使用指南 |
| 工作坊示範 | 讓參與教師實際經歷預判、AI協作、驗證與變式 | 完成至少1場工作坊及匿名回饋摘要 |
| 研究交流 | 將正面、無差異與負面結果一併投稿或報告 | 至少1次研討會／成果展投稿與1篇論文投稿 |

### 三、預期的長期價值

本計畫最重要的長期貢獻，不是建立另一套防堵AI的作業，而是提出一種可移植的設計原則：當AI能完成大部分表面任務時，課程仍可透過「學生先形成判斷—使用AI協作—以外部證據驗證—說明因果—在新情境中遷移」保留學生的認知責任。若研究結果支持預期，此模式可作為工程與資訊實作課程調整評量的參考；若結果未完全支持，也能具體指出哪些介入成分負荷過高、哪些學生需要更多鷹架，以及哪些證據最能或最不能反映真實學習。
