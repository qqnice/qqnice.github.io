CORE CONCEPTS

先把五個名詞放進腦中的同一張圖

點擊每一張卡片，可展開它在 WEEK1 裡扮演的角色。

Dockerfile→Image→Container→Port→Volume→Network
📦

Image

映像檔：系統／應用程式的安裝模板。

可以把它想成「還沒開機的應用程式模板」。同一個 Image 可以建立很多 Container。
🧊

Container

Image 實際執行後的環境。

Container 有自己相對獨立的檔案系統與套件，但和 Host 共用 Linux 核心。
🔌

Port

把 Host 的入口對應到 Container 內的服務。

-p 8080:80 代表 Host 8080 → Container 80。
💾

Volume / Mount

把重要資料與 Container 分離。

WEEK1 先學 Bind Mount：Host 目錄直接掛進 Container，修改 Host 檔案即可立即反映。
Registry / Docker Hub： Registry 是存放 Image 的地方；Docker Hub 是公開 Registry，可以把它想成 Docker Image 的 GitHub。
HANDS-ON LAB

七個實作，從 Hello World 走到自己的 Image

展開每一關查看指令。做完可勾選「已完成」，頁面會記錄本機瀏覽器的進度。

cat /etc/os-release
sudo apt update
sudo apt upgrade -y

sudo apt install -y docker.io
docker --version

sudo apt install -y docker-compose-v2
docker compose version

sudo systemctl enable --now docker
sudo usermod -aG docker $USER
newgrp docker
加入 docker 群組後，一般使用者可直接執行 docker；但 docker 群組成員等同擁有很高的系統權限，正式伺服器要謹慎。
docker run hello-world

docker images
docker ps
docker ps -a
如果本機沒有 ImageDocker 會先從 Registry 下載。
接著建立 Container 並執行程式。
Hello World 結束後Container 停止，但仍可在 docker ps -a 看見。
docker pull ubuntu:24.04
docker run -it ubuntu:24.04 bash

cat /etc/os-release
apt update
apt install -y curl
curl --version
exit

看到 root@xxxx:/# 就代表已經進入 Container。你可以在裡面安裝套件，而 Host 的套件環境不會因此直接被修改。

docker run -it --name myubuntu ubuntu:24.04 bash
exit

docker ps -a
docker start myubuntu
docker stop myubuntu
docker restart myubuntu
docker rm myubuntu
docker rm -f myubuntu

docker run 是「建立＋執行」；start 則是啟動已經存在的 Container。

docker pull nginx
docker run -d --name myweb -p 8080:80 nginx

docker ps
docker logs myweb
docker logs -f myweb

瀏覽器開 http://localhost:8080，預期看到 Welcome to nginx!。

docker exec -it myweb bash

cd /usr/share/nginx/html
ls
cat index.html
exit

exit 只是離開 shell；Nginx Container 仍然在背景執行。

docker rm -f myweb

mkdir -p ~/docker-lab/website
nano ~/docker-lab/website/index.html

docker run -d --name myweb -p 8080:80 \
  -v ~/docker-lab/website:/usr/share/nginx/html:ro \
  nginx

修改 Host 上的 index.html 後重新整理瀏覽器，內容會立即改變。:ro 表示 Container 只能讀取。

mkdir ~/mydocker
cd ~/mydocker
nano Dockerfile
FROM ubuntu:24.04

RUN apt-get update && \
    apt-get install -y curl && \
    rm -rf /var/lib/apt/lists/*

CMD ["bash"]
docker build -t myubuntu:v1 .
docker images
docker run -it myubuntu:v1
curl --version
exit
Dockerfile 中建議使用 apt-get 而不是 apt；而 docker build -t myubuntu:v1 . 最後的「.」代表目前目錄，不能漏掉。

DATA & BUILD

資料怎麼保存？Image 又怎麼自己做？

WEEK1 先把 Bind Mount 與 Dockerfile 建立 Image 兩件事分開。

Bind Mount

Host 的真實目錄直接掛進 Container。

Host: ~/docker-lab/website
          ↓
Container: /usr/share/nginx/html

適合練習網站檔案與設定檔：Host 一修改，Container 馬上讀到。

Named Volume（下一週預告）

由 Docker 管理資料位置。

db-data:/var/lib/mysql

WEEK1 先知道這個名詞；WEEK2 的 WordPress / MariaDB 會正式使用。

WEEK1 指令地圖

知道每一條指令是在操作 Image、Container、Log 還是 Build，比背完整語法更重要。

docker pull nginx下載 Image

docker run nginx建立＋執行 Container
docker ps / docker ps -a查看 Container

docker logs NAME看執行紀錄
docker exec -it NAME bash進入執行中的 Container
docker inspect NAME查看詳細設定
docker build -t name .建立自己的 Image
docker compose up -dCompose 前導
docker compose down關閉 Compose Application
