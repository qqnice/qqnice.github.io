步驟 01 · CONNECT

瀏覽器 8 碼安全授權

請 Antigravity 啟動 gh auth login --web，再到真實頁面 github.com/login/device 輸入 8 碼按 Authorize，免貼密碼或金鑰。

步驟 02 · CREATE & PUSH

一句 Prompt 建 Repo 並推送

直接複製本頁 Prompt 貼入 Antigravity，自動建立 .gitignore、完成首次 Commit 並推送到 GitHub 新儲存庫或既有專區。

步驟 03 · PAGES

自動發佈 GitHub Pages

請 Antigravity 設定從分支發佈 GitHub Pages（或推送到 qqnice.github.io/linux/ 等子資料夾），自動取得公開網址。

步驟 04 · VERIFY

對照真實頁面驗收

推送完成後，核對 Commit 連結、GitHub Actions 部署狀態與公開網址，確認沒有把密碼、Token 或個資上傳公開。

    Part 3 · 常見問題與「貼給 Antigravity 的一句話排解 Prompt」速查表
    
        
    在串接或推送過程中如果遇到錯誤訊息，不需要自己查英文 Stack Overflow，直接複製右欄的 Prompt 貼給 Antigravity 即可自動修復：
    
        
    
          
    
            
              
    
                常見卡關狀況
                直接貼給 Antigravity 的排解 Prompt
              
    
                
            
              
    
                1. 找不到 gh 指令（command not found: gh）
                請幫我檢查系統環境並用 Homebrew 或官方安裝方式安裝 GitHub CLI (gh)，安裝完成後執行 gh --version 確認。
              
    
              
    
                2. 推送時出現 403 或 Permission denied
                我推送到 GitHub 時遇到權限錯誤，請幫我用 gh auth status 檢查目前登入的帳號與 token 權限，並執行 gh auth setup-git 綁定 Git 憑證。
              
    
              
    
                3. 遠端有新變更導致無法直接 Push（Rejected / Non-fast-forward）
                遠端 GitHub 儲存庫有其他人或另一台電腦推上去的更新，請幫我先 git fetch 並用 git pull --rebase 安全整合遠端變更，再重新推送到 GitHub。
              
    
              
    
                4. 不小心把 .DS_Store 或暫存檔加進去了
                請幫我從 Git 追蹤清單中移除 .DS_Store 與不該上傳的暫存檔（保留本機檔案），更新 .gitignore 並重新提交推送。
              
    
              
    
                5. 發佈後點網址卻顯示 404 Not Found
                我剛推送了網頁檔案到 GitHub，請幫我檢查目標儲存庫的 GitHub Pages 發佈分支（main 或 master）、路徑大小寫與 Actions 部署狀態，確認公開網址何時生效。
