DEVELOPMENT FLOW

四個階段，每一關都要驗證

不要一次貼完整答案。每個階段完成後先 Checkpoint，再進下一個架構層次。

01STEP 1–6

Compose 與 Network

把 WEEK1 的 docker run 改寫成 compose.yml，再從單一服務走向 Multi-container。

  • 第一份 compose.yml
  • Nginx + Apache 兩服務
  • 理解 image / build / ports
  • 觀察 Compose default network
  • 用 service name 找到另一個 Container
CHECKPOINT 
curl http://localhost:8080
curl http://localhost:8081

02STEP 7–12

WordPress + MariaDB + Volume

建立應用程式與資料庫服務，並先做好 Named Volume，避免重要資料綁死在 Container。

  • MariaDB service：db
  • WordPress service：wordpress
  • WORDPRESS_DB_HOST=db
  • db-data / wp-data
  • 驗證 WordPress 已連上 DB
CHECKPOINT 
docker volume ls
docker compose logs db
curl -I http://localhost:8082
03STEP 13–18

Reverse Proxy 與 DNS

移除後端的公開 Port，讓 Nginx 成為唯一入口，再用 Host 標頭把兩個 Domain 導向不同服務。

  • 刪除 hello 與 8081 / 8082 publish
  • 新增 Nginx :80 / :443
  • server_name + proxy_pass
  • Host header 分流實驗
  • DNS → 同一 Public IP
CHECKPOINT 
curl -H "Host: s123456.qqnice.org" http://127.0.0.1/
curl -H "Host: k123456.kknice.net" http://127.0.0.1/
04STEP 19–29

Let's Encrypt 與 HTTPS

先用 HTTP-01 完成驗證，再從 Staging 走到正式憑證，最後切 HTTPS、安裝 WordPress、驗證續期。

  • ACME challenge 測試
  • Staging → 正式憑證
  • HTTP 301 → HTTPS
  • SNI + 正確憑證
  • Persistence
  • renew --dry-run + cron
CHECKPOINT 
curl -I https://s123456.qqnice.org
curl -I https://k123456.kknice.net
docker compose run --rm certbot renew --dry-run

DNS 與 Nginx 的分工

DNS 只把 Domain 轉成 IP；Nginx 再看 Host / SNI 決定網站與憑證。

為什麼後端沒有 Public Port？

Nginx 與後端都在同一 Compose Network，可直接用 wordpress:80、web:80。

Container ≠ Data

文章、帳號、圖片與外掛使用 Named Volume 持久保存。

HTTPS FLOW

憑證流程一定要照順序

先確定 HTTP-01 從 Internet 可讀，再碰正式憑證。全班共用 registered domain 時尤其重要。

取得憑證

DNS OK→ ACME test.txt OK→ Staging OK→ 教師確認→ Production

啟用 HTTPS

  • Port 80 保留 /.well-known/acme-challenge/
  • 其他 HTTP Request 301 到 HTTPS
  • 443 依 SNI 選擇憑證
  • Nginx 將 X-Forwarded-Proto 傳給 WordPress
  • WordPress 第一次正式安裝一定從 HTTPS Domain 進入
