KVM 全虛擬化（QEMU 11.1） 獨立作業系統核心

每台 VM 擁有完全獨立的虛擬硬體與 OS 核心。適合跑 Windows Server、異質 Linux 發行版、或需要高度安全隔離的環境。

  • 支援 x86（VT-x/AMD-V）及 Armv9-A 以上 64 位元處理器
  • 支援 PCIe 硬體直通（VT-d / AMD-Vi）與 vTPM qcow2 離線快照
  • PVE 9.1+ 提供精細巢狀虛擬化 vCPU 旗標控制
LXC 輕量容器（LXC 7.0 + OCI） 共享宿主機核心

所有容器共享 PVE 宿主機的 Linux 核心，開機只要 1–2 秒、記憶體開銷極低，特別適合高密度 Linux 服務（網頁、資料庫、微服務）。

  • PVE 9.1 起可直接從遠端 Registry 下載 / 上傳 OCI 映像檔建立容器
  • 實務提醒：官方對 OCI 直接作為 PVE 容器層仍偏技術預覽，企業生產導入前應先驗證穩定性與更新流程。

展開進階架構小百科：PVE 9.0–9.3 高可用與儲存三策略

HA 智慧排程演進（9.0 → 9.3）

  • PVE 9.0 親和性規則：可設定相依服務同主機降延遲，或強制冗餘服務分散不同節點。
  • PVE 9.2 動態負載平衡器：依資源消耗自動熱遷移；新增維護 Arm/Disarm，維護完自動歸位。
  • PVE 9.3 GUI 維護模式 & 唯一客體識別碼：遷移、快照回滾、備份還原皆維持同一個識別碼不混亂。

企業高可用儲存三種策略

  • 3–10 節點超融合（HCI）：同組伺服器跑 PVE + Ceph，無單點故障，但須留意重平衡頻寬。
  • 外部獨立 Ceph 叢集：運算與儲存實體分離，避免復原時搶 CPU/網路，還可對外提供 S3。
  • 既有企業 SAN 利舊（9.3 重大突破）：共用 LVM 磁碟區鏈快照正式投產，加上集中式 Datacenter > SAN 多路徑設定精靈。

坑 01 · 硬體相容

嚴禁硬體 RAID 搭 ZFS / Ceph

磁碟控制器必須刷為 HBA 直通模式。若本機一定要用硬體 RAID，請搭配 BBU 電池快取並改用 LVM，千萬別疊加 ZFS 或 Ceph。

坑 02 · 網路與節點

10GbE 網路 ＋ 仲裁門檻

生產級 HA 與 Ceph 需配置 10 Gbps 以上冗餘網路，標準由 3–10 節點起步；僅 2 節點時必須加裝外部 QDevice 仲裁主機。

坑 03 · 生態系差異

PDM 1.1 尚非完整版 vCenter

PDM 1.1 尚缺跨叢集自動 DRS、單一 VM 權限委派與集中備份；Veeam 暫不支援 LXC；NVIDIA vGPU 未涵蓋 AI Enterprise 純運算設定檔。

坑 04 · 維運能力

需具備 Debian Linux 除錯力

Web 介面很直覺，但遇到 Ceph 效能調校、Corosync 延遲或 BGP/EVPN SDN 排錯時，仍考驗扎實的 Linux 網路與儲存功底。
