Real case / 04

同一個 IP，兩個網域，如何找到正確的 Container？

DNS 只負責把網域帶到同一個 IP。真正看著 HTTP Host 並將請求分流的，是最前面的 Reverse Proxy。

你是瀏覽器，請選擇一個網域

觀察請求如何經過「門口接待」，被送到不同的服務。

為什麼不能兩個都用 80:80？
Host 的同一個 IP 與 Port 80 只能有一個入口。先由 Reverse Proxy 接收，再轉送到內部 Container。

Compose / 05

Compose 是整間餐廳的開店計畫

它不會把所有程式塞進同一個 Container；它用一份 YAML 一次定義多個服務、網路、Port 與 Volume。

compose.yml概念示意
services:
  proxy:
    image: nginx
    ports: ["80:80"]

  apache:
    image: class-apache:1.0

  wordpress:
    image: wordpress
    environment:
      WORDPRESS_DB_HOST: db

  db:
    image: mariadb
    volumes:
      - db-data:/var/lib/mysql

volumes:
  db-data:
Compose internal network
proxy唯一對外入口
apache靜態網頁
wordpress網站應用
dbMariaDB + Volume

proxy 是門口接待。它佔用 Host 的 Port 80，但其他服務只在內部 Network 中接受轉送。

Misconceptions / 06

在動手之前，先拆掉三個誤解

名詞會背不等於真的理解。如果能說清楚下面三組差異，就已經抓住 Docker 的核心。

✕ Image 就是 Container

✓ 模板 ≠ 執行實體

Image 不會自己提供服務；可從同一個 Image 啟動多個互不相干的 Container。

✕ EXPOSE 80 就能從外部連線

✓ 還要發布 Port

EXPOSE 像標記廚房預期使用的窗口；-p 8080:80 才是把 Host 入口真正接上去。

✕ Container 裡的 localhost 是 Host

✓ localhost 是它自己

WordPress 找資料庫時，不應寫 localhost，而是透過 Network 使用 Compose 服務名 db。
