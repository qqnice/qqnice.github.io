114-2 FINAL PROJECT

單主機多服務架構與地端 AI 部署

這不只是一場期末測驗，而是你成為專業雲端工程師的「職前訓練」。你將在單一節點上整合原生服務、容器化架構，並成功部署當紅的大型語言模型。

核心架構要求

基礎設施 (IaaS)

  • Azure VM 環境
  • CPU 4 Core / RAM 16GB
  • HDD 120GB (AI 模型需求)
  • 統一綁定 NUTC DNS

混合式服務部署

  • Nginx 反向代理總機
  • 原生 WordPress (Socket)
  • Docker 版 WordPress

地端 AI 應用

  • Ollama + Open WebUI
  • 載入 Gemma4:2B 模型
  • 嚴格的測試帳號權限控管

實作拆解藍圖

遇到困難？一步一步來，分而治之。

基礎設施層 (IaaS)

1. 架構規劃 (Notion)： 在動手前，先規劃好 3 個子網域、Nginx 轉發 Port 以及防火牆規則。

2. 淨空驗證： 截圖證明 Azure 虛擬機器列表為空 (需含系統時間)。

3. 開通 VM： 嚴格依照 4 Core / 16GB / 120GB 規格建立虛擬機。

4. 防火牆 (NSG)： 開放 Port 22 (SSH), 80 (HTTP), 443 (HTTPS)。

重大警告：IP 綁定不可逆 確認 DNS 解析無誤再綁定。若因操作失誤需改 IP，重扣 10 分！

中介軟體層

1. 更新系統： sudo apt update && sudo apt upgrade

2. 安裝 Nginx： 擔任總機，負責接收並分發外部流量。

3. 安裝 Docker 環境： 安裝 Docker Engine 與 Docker Compose。

4. 安裝 PHP/DB： 為原生 WP 準備 PHP-FPM 與 MariaDB/MySQL 環境。

5. 準備 SSL 工具： 安裝 Certbot，為最後階段做準備。

應用服務層 (先確保 Localhost 暢通)

原生 WordPress

採用 Socket 通訊。首頁必須展示你的真實照片與姓名。

Docker WordPress

透過 docker-compose 建置。首頁只能顯示「你的學號」。

AI Server

部署 Ollama + WebUI。載入 Gemma4:2B。建立非管理員測試帳號。

整合與加密層

1. Nginx 虛擬主機： 為三個網域分別撰寫 .conf 設定檔。

2. 精準轉發 (Proxy Pass)： 分別將流量導向 .sock 路徑及 Docker 對應的主機 Port。

3. 申請 SSL 憑證： 執行 Certbot，自動配置 HTTPS 並強制重導向。

4. 無痕驗證： 開啟無痕視窗，親自測試三個網址是否安全且畫面符合規格。

為什麼規定這麼多？業界紀律解密

業界真實場景： 在商用環境中，DNS 擴散需要數小時甚至數天。隨意變動 Production 環境的固定 IP，會直接導致服務中斷 (Downtime) 與大量客訴。這項規定是為了讓各位提早體會「每一次 Enter 鍵敲下去都要負責」的壓力。
業界真實場景： 這對應了業界的「系統日誌 (Log) 與事件稽核」精神。發生資安事件或系統當機時，精確的時間點與操作軌跡是釐清責任的唯一依據。「有圖有真相，且時間要對得上」是系統工程師保護自己的基本功。
業界真實場景： 系統建置完不能只丟一個網址給主管或客戶。撰寫維護手冊、交接文件是工程師的職責。一個缺乏文件紀錄的系統，對企業來說就是巨大的「技術債」。
