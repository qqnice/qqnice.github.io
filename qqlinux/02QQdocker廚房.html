第一章
傳統廚房的悲劇

為什麼我們需要 Docker？

你租了一個很大的空地（Server / Ubuntu 主機），蓋了一個大廚房。你決定同時賣三種料理：四川麻辣鍋、法式精緻甜點、義大利麵。

🏚️ 情境：同一間廚房，三種衝突料理

麻辣鍋的爐火、甜點的恆溫要求、義大利麵的大量沸水——全部擠在同一個空間裡，只會發生一件事：

  • 互相污染（環境衝突） 麻辣鍋的辣椒粉飄到了法式蛋糕上，甜點毀了。技術上是：A 系統需要 Python 2.7 的舊版套件，覆蓋了 B 系統需要的 Python 3.11，兩個都掛掉。
  • 一人生病，全家遭殃（缺乏容錯） 學徒不小心把油鍋打翻引發火災，不僅麻辣鍋不能賣，連法式甜點和義大利麵也跟著停擺，整間餐廳關門大吉。
  • 新人要花三天才能上工（環境建置困難） 每次招募新學徒，都要重新教他採購鍋具、接瓦斯管、調整火力……光建置環境就花掉三天。
第二章
核心觀念

Docker 魔法廚房降臨

引進了 Docker 魔法系統之後，整個廚房的運作方式徹底改變。以下是三個核心觀念：

🏗️

Server（主機）

Ubuntu / Cloud VM

只是提供水電和空地的基礎設施。它什麼料理都不做，只負責讓泡泡們存在。

基礎設施
🫧

Container（容器）

docker run

魔法獨立小廚房泡泡。有完整爐子、鍋子、水源——跟隔壁泡泡完全不共用。壞了就戳破重蓋。

隔離 · 容錯
🧊

Image（映像檔）

docker image

名廚製作的標準化冷凍廚房模組。唯讀的母版，永遠不被改動。解凍展開就是 Container。

唯讀 · 母版
💡
Image 是唯讀的！ 這個冷凍模組是「母版」，它永遠不會被改動。你從它解凍出一個容器，是在製作複印本——不管複印本被燒爛幾次，母版永遠完好如初。
✨
同時複製的超能力： 週末訂單暴增？同一個廚房模組，可以同時變出三間義大利麵小廚房一起開工，週一再收掉兩間。這就是「水平擴展」（Scaling）的概念。
第二‧五章
Image 的來源

Dockerfile 與 Docker Hub

學生常常問：「這個冷凍模組，是誰做出來的？」答案有兩種：自己做，或去賣場拿。

🗒️

Dockerfile

製作冷凍模組的食譜卡

一張指令清單，告訴 Docker 工廠按步驟製作模組。執行 docker build 就能產出 Image。

自訂模組
🏬

Docker Hub

冷凍食品大賣場

全球最大的模組賣場，nginx、mysql、node 等現成模組全部免費取用。docker pull 直接下載。

現成模組
Dockerfile 範例
# 以官方 Ubuntu 模組為基礎 FROM ubuntu:22.04 # 安裝義大利麵專用環境 RUN apt-get install -y nodejs npm # 把我的獨家程式碼放進去 COPY ./my-app /app # 廚房開始時執行的命令 CMD ["node", "/app/server.js"]
🎯
學習捷徑： 初學者九成的時間，都是直接從 Docker Hub 取用現成模組，再用 Dockerfile 做小幅度客製化。不需要從零開始造輪子。
第三章
自動化點菜單

docker-compose.yml

一個完整的網站，通常需要好幾間廚房同時運作：點餐窗口、食材倉庫、外送接單……手動逐一變出泡泡既容易出錯又麻煩。

docker-compose.yml
# 工頭，請幫我蓋好以下整間餐廳： services: web: # 點餐窗口廚房 image: my-app ports: - "9000:80" # 街上9000號 → 廚房內部80號 depends_on: - db db: # 食材倉庫冰庫 image: mysql:8 volumes: - db-data:/var/lib/mysql volumes: db-data: # 永久大冰箱

✨ 魔法工頭指令

docker compose up -d → 一分鐘內，整間餐廳蓋好開張
docker compose down → 所有泡泡收走，空地恢復清爽
Port 連接埠說明

Port 就是廚房的傳菜口編號。容器是個密閉的泡泡，外面的客人（瀏覽器）必須透過指定的窗口才能進來。

瀏覽器
localhost:9000
→
主機大門
Port 9000
→
容器內部
Port 80

設定 "9000:80" → 街上 9000 號大門，接通廚房內部 80 號傳菜口

第四章
最重要的一課

Volume 儲存卷：保住客人的訂單

這是所有新手最常犯的致命錯誤。

😱 情境：消失的蛋糕

學徒把做好的精美法式蛋糕（你的網站文章、資料庫記錄）放在魔法小廚房的桌上。當你把這個小廚房「波！」一聲收掉時，裡面的蛋糕就跟著灰飛煙滅了！

⚠️
這不是 Bug，這是 Docker 的設計哲學： 容器要能隨時被銷毀和重建，以此保證環境永遠純淨一致。因此資料絕對不能住在容器裡。
🧊

Volume（儲存卷）

廚房外的永久大冰箱

在真正的餐廳空地（Ubuntu 主機）上，安裝一台永久大冰箱。用魔法管子把泡泡裡的備料區和外面的大冰箱連通——資料直接存進主機硬碟，容器可以刪了重建幾百次都不影響。

資料持久化
Volume 對應示意
# 把容器內的路徑，接到主機的永久資料夾 volumes: - ./db-data:/var/lib/mysql ↑ 主機硬碟 ↑ 容器內路徑 (永久大冰箱) (廚房備料架)
✅
結果： 不管你把魔法小廚房刪除幾百次、升級幾十次、換到不同伺服器，只要大冰箱（Volume）還在，你的所有資料就永遠安全。
