電梯套件 ElevatorKit
學生操作手冊

電梯的外觀、按鈕偵測、門板、顯示器都已經做好。你要在 BP_ElevatorKit 裡寫出「電梯什麼時候該做什麼」。這份手冊一步一步告訴你要開哪個檔案、點哪裡、用哪些節點。

整份作業只需要編輯一個檔案Content/ElevatorKit/BP_ElevatorKit。地圖、材質、名稱開頭是 Kit_ 的函數，都不要修改。

1拿到哪些檔案

Content/ └─ ElevatorKit/ ├─ BP_ElevatorKit ← 你唯一要編輯的 Blueprint ├─ Materials/ 電梯與樓梯的材質（不要動） └─ Maps/ └─ Lvl_ElevatorKit_Demo 練習地圖：兩層樓空殼房子 + 樓梯 + 電梯井

練習地圖本身沒有任何程式。電梯的所有程式都在 BP_ElevatorKit 裡，所以寫完之後，只要把這個 BP 放進你自己的場景就能用（第 14 節）。

2打開練習地圖，先試玩一次

  1. 在 Content Browser 依序點進 Content → ElevatorKit → Maps。
  2. 雙擊 Lvl_ElevatorKit_Demo。如果跳出「要不要存檔」的對話框，存你自己原本開著的地圖即可。
  3. 按工具列上的綠色 ▶ Play。
  4. 你會出生在房子正面外側。往前走進房子，電梯在最裡面；旋轉樓梯可以走上 2F。
  5. 走到電梯門前（約 2.5 公尺內），按 E。

畫面左上角會出現 TODO: OnCallButtonPressed，樓層 1。這代表按鈕偵測正常，接下來要由你寫程式。按 Esc 結束試玩。

3打開 BP_ElevatorKit

  1. Content Browser 回到 Content → ElevatorKit。
  2. 雙擊 BP_ElevatorKit（縮圖是一個小電梯，下方寫 Blueprint Class）。
  3. Blueprint 編輯器會在新視窗打開。視窗太小的話，按右上角的「最大化」。
不要雙擊場景裡的電梯在關卡裡選到電梯 EV 再點 Details 的「Edit BP_ElevatorKit」也會開到同一個 BP，但新手容易改到關卡裡那一台的設定值。請一律從 Content Browser 打開。

4認識 BP 編輯器

編號區域這次會用來做什麼
①Components電梯的零件（車廂、門板、按鈕、顯示器）。只看不改。
②My Blueprint最常用。Graphs、Functions（函數）、Variables（變數）都在這裡。雙擊函數名稱就會打開它。
③圖表區拉節點、接線的地方。上方的分頁可以切換已打開的函數。
④Details選到什麼就顯示什麼的設定：變數的型別與預設值、函數的輸入參數。
⑤Compile每次改完都要按。圖示變成綠色勾勾才代表沒有錯誤。
⑥Save存檔（Ctrl+S）。Compile 不等於存檔。

圖表區操作：按住滑鼠右鍵拖曳移動畫面，滾輪縮放，按 Home 把所有節點縮放到畫面內。

在 My Blueprint 的 GRAPHS 底下雙擊 EventGraph，看看套件幫你接好了什麼。這一頁的接線決定了「玩家做了什麼動作，就呼叫哪個函數」。

按 1 / 2Kit Cabin KeyOnCabinButtonPressed（只有在車廂裡才會呼叫）
按 EKit Try Press Button站在某層門外 → OnCallButtonPressed（在車廂裡按 E 不會有反應）
進入／離開 TriggerBoxKit Refresh Cabin Light（車廂燈，不用管）
Timeline 的 UpdateUpdate LiftUpdateLift，每一幀都會執行一次
看到「This node is disabled and will not be called」是正常的那是 Unreal 預設放的灰色事件節點（ActorBeginOverlap、Tick），沒有接線所以不會執行。不用刪，也不用接。

6設定值與你自己的變數

在 My Blueprint 展開 VARIABLES，會看到兩個分類：

電梯設定（可以讀，也可以調）

變數預設值意思
FloorHeights[0, 500]每層車廂的高度（cm）。索引從 0 開始：1F 是索引 0，2F 是索引 1

DwellTime3.0門全開後停留幾秒

給 Kit_ 函數用的。不要讀也不要寫。

你要新增的 7 個變數

電梯「現在在第幾層」、「正在做什麼」、「門開了多少」這些資料，套件沒有提供。下表列出整份作業會用到的全部變數，請照表自己新增。名稱、型別、預設值都要和表上一致，之後看手冊和問老師才對得起來。

名稱型別預設值意思從第幾關開始用
StateInteger0電梯現在在做什麼（見下方的狀態編號）關卡 1
CurrentFloorInteger1電梯停靠（或剛離開）的樓層，1 或 2關卡 1
TargetFloorInteger1正在前往的樓層，1 或 2關卡 1
DoorAlphaFloat0.0門開了多少：0 = 全關，1 = 全開關卡 2
DwellRemainingFloat0.0門全開後，還要再停幾秒關卡 2
DirectionInteger0移動方向：1 = 上，−1 = 下，0 = 停關卡 3
RequestsBoolean 陣列[false, false]（兩格）每一層有沒有人在等：第 0 格 = 1F，第 1 格 = 2F關卡 4

State 的編號（請照這個約定使用）：

值狀態門
0待命關著
1開門中從 0 開到 1
2停留全開，倒數 DwellRemaining
3關門中從 1 關到 0
4移動中關著

關卡 1 只會用到 0（待命）和 4（移動中），其他狀態到關卡 2 才用。

這些變數什麼時候該改成什麼值、在哪個函數裡改，才是這份作業要你想的部分。

新增變數的方法

  1. 在 My Blueprint 的 VARIABLES 那一列按右邊的 ⊕。
  2. 輸入名稱後按 Enter。名稱用英文，看名字就要知道用途。
  3. 在 Details 的 Variable Type 選型別：整數用 Integer，小數用 Float，是／否用 Boolean。需要陣列的話，點型別右邊的圖示改成 Array。
  4. 在 Details 的 Category 輸入 我的變數，方便和套件的變數分開。
  5. 按 Compile，Details 下方才會出現 Default Value，在那裡填初始值。
  6. Requests 是陣列：Compile 後在 Default Value 按兩次 ⊕ 加入兩格，兩格都不要打勾。

預設值是 0 的 Integer、0.0 的 Float 不用另外填，新增時就已經是 0。

在圖表裡使用變數：從 My Blueprint 把變數拖進圖表區，放開時選 Get（讀取）或 Set（寫入）。快捷鍵是按住 Ctrl 拖曳為 Get，按住 Alt 拖曳為 Set。

7打開你要寫的函數

7 個函數都已經建好了名稱和輸入參數也都設好了。你不用新增這 7 個函數，只要在 My Blueprint 雙擊打開，把裡面的內容補上。唯一要你自己新增的是關卡 4 的 FindRequest（第 12 節）。
這一節只要做兩件事，還不用拉節點① 把下面每個函數打開看一次，認識它的入口節點和輸入參數。② 看一下 OnCallButtonPressed、OnCabinButtonPressed 裡的 TODO 訊息，它可以保留當除錯用（本節最後）。參數不用輸入，已經建好了。真正開始拉節點、接線，是從第 9 節關卡 1 開始。

在 My Blueprint 的 FUNCTIONS 底下雙擊函數名稱，圖表區就會打開那個函數，上方多一個分頁。也可以在 My Blueprint 的搜尋框輸入名稱，比較快找到。

輸入參數在哪裡看得到：打開函數後，紫色入口節點右邊的綠色接腳（例如 Floor），以及右側 Details 的 Inputs 區。它代表「別人呼叫這個函數時帶進來的樓層號碼」，你不用輸入，寫內容時拿 Floor 接腳去接其他節點就好。

「拉節點、接線」是什麼意思：從入口節點的白色箭頭 ▷ 往右拉，放進 Branch、Set 變數、Kit 函數、數學運算等節點，把線接起來組成判斷。大部分不是填數字，只有少數地方要填值（例如 Set State 填 4）。節點數是依參考寫法估計，你的寫法多一點或少一點都沒關係。

OnCallButtonPressed 與 OnCabinButtonPressed：TODO 訊息可以保留當除錯用

  1. 這組節點只會在畫面上印一行字，不影響電梯運作。建議保留：每次按按鈕都能確認「這個函數有被呼叫、樓層是幾」。
  2. 可以把 Append 的 A 欄文字改成你自己的訊息，例如 按了呼叫鈕，樓層 ，避免以為還沒做完。
  3. 到關卡 1、2 寫內容時，新節點要從 Print String 右邊的白色箭頭 ▷ 繼續往後接，不要從入口節點另外拉一條線（一個 ▷ 只能接一條）。
  4. 綠色的 Floor 接腳就是被按的樓層，拖曳它就能接到其他節點的 Floor 輸入。同一個接腳可以拉出好幾條線。
  5. 全部完成、不再需要除錯時，再框選 Append、Print String 和中間的轉換節點刪掉，並把入口節點直接接到後面的節點。

其他空殼函數

空殼函數只有入口節點，從入口的 ▷ 往右接就可以了。函數沒有回傳值，不需要 Return 節點。

在一個函數裡呼叫另一個函數從 My Blueprint 把函數名稱拖進圖表區，或在圖表區按右鍵搜尋名稱，例如在 OnCallButtonPressed 裡放一個 Call Elevator 節點。

8放入 Kit 節點

Kit 是什麼？Unreal 原本沒有這些函數。它們是電梯套件（ElevatorKit）另外寫好、提供給你用的普通 Blueprint 函數。名稱前面統一加上 Kit_ 有三個用處：① 一眼分出誰寫的：Kit 開頭的是套件寫好的，沒有 Kit 的（OnCallButtonPressed、UpdateLift……）是你要寫的；② 好找：右鍵搜尋時打 Kit 就會一起列出來；③ 提醒不要改：拿來呼叫就好，不要打開修改。這跟 Unreal 專案常見的命名習慣一樣，例如 Blueprint 用 BP_ 開頭、材質實例用 MI_ 開頭。
這一節只是說明，還不用真的放節點這一節教你怎麼找到 Kit 節點、看懂它們的接腳。真正要放哪些節點、放在哪個函數，第 9～12 節每一關的「要編輯的地方」會寫清楚。例如關卡 1 才會在 UpdateLift 裡放 Kit Get Lift Z、Kit Set Lift Z、Get World Delta Seconds。想先試試看，可以放一個再按 Delete 刪掉。
先打開你要寫的函數，再按右鍵節點要放在你正在寫的函數裡。例如寫關卡 1 時，先在 My Blueprint 雙擊 UpdateLift，在 UpdateLift 的分頁裡按右鍵。不要放在 EventGraph：EventGraph 是套件接好的（第 5 節），放在那裡的節點沒有接在任何事件後面，永遠不會執行。

在函數分頁的空白處按右鍵，搜尋框輸入 Kit，就會列出所有套件函數。點一下就會放進圖表。

你會用到的只有這幾個：

  • Kit Get Lift Z
  • Kit Set Lift Z
  • Kit Apply Doors
  • Kit Is Door Blocked
  • Kit Is Player in Cabin
  • Kit Set Button Light
  • Kit Update Displays

其他 Kit 函數（Setup、Cabin Key、Try Press Button、Find Call Button Floor、Display Floor、Refresh Cabin Light）是套件內部或 EventGraph 在用的（開始遊戲、按 1/2、按 E 時自動呼叫），整份作業都不會用到，不要放進你的程式。

節點輸入輸出做什麼
Kit Get Lift ZZ（Float）車廂目前高度。0 = 1F，500 = 2F
Kit Set Lift ZZ把車廂移到高度 Z。每幀呼叫、每次移一點，看起來就是在動
Kit Apply DoorsAlpha, Floor擺好門的位置。Alpha 0 = 全關，1 = 全開，0.5 = 開一半。車廂門和第 Floor 層的井口門一起動

Kit 節點都有白色執行箭頭連 Kit Get Lift Z、Kit Is Door Blocked 這種查詢用的節點也有 ▷。它們一定要串在白色執行線上，否則不會執行，輸出的值也不對。

9關卡 1：會動

目標：在車廂裡按 2，電梯從 1F 移到 2F 停住；按 1 回到 1F。這一關不用管門和燈。

先在紙上回答

  • 按下 2 之後，State、TargetFloor、CurrentFloor 各在什麼時候、被哪個函數改成什麼值？
  • 每一幀車廂要移動多少距離？跟 MoveSpeed 和這一幀的秒數有什麼關係？
  • 怎麼判斷「到了」？

架構：這一關做完後，各層之間的關係

關卡 1 只有一條路：在車廂按 1／2，OnCabinButtonPressed 直接呼叫 StartMove 記下目標；之後每一幀 UpdateLift 只要判斷「是不是移動中」，是就把車廂移一步，到站呼叫 OnArrived。

要編輯的地方

  1. 照第 6 節的表，先新增 State、CurrentFloor、TargetFloor（也可以一次把 7 個都建好）。
  2. 打開 OnCabinButtonPressed，在 Print String 後面呼叫 Start Move 並把 Floor 接過去。（之後的關卡會改成呼叫 CallElevator。）
  3. 打開 StartMove：把傳進來的 Floor 存進 TargetFloor，再把 State 設成 4（移動中）。做法：按住 Alt 把變數拖進圖表得到 Set 節點，白線依序接 入口 ▷ → Set TargetFloor → Set State；Floor 接腳拉到 Set TargetFloor 的輸入，Set State 填 4。StartMove 只負責下指令，真正讓車廂動的是 UpdateLift。
  4. 打開 UpdateLift：如果 State 是 4（移動中），就讀目前高度（Kit Get Lift Z）、算這一幀要移多少、寫回新高度（Kit Set Lift Z）。到了就呼叫 On Arrived。State 不是 4 時什麼都不做。
  5. 打開 OnArrived：把 TargetFloor 存進 CurrentFloor（現在停在這一層了），再把 State 設回 0（待命）。OnArrived 沒有 Floor 輸入，這是刻意的：目的地早就被 StartMove 存在 TargetFloor 裡，按住 Ctrl 拖出 Get TargetFloor 讀出來就好。函數之間就是這樣靠變數傳遞資料。
  6. Compile → Save → 回主視窗按 Play 測試。

步驟 2～5 是照程式執行的順序排（按下按鈕 → 出發 → 每幀移動 → 到站），方便理解。實際上先寫哪一個都可以：函數都已經存在，呼叫一個還是空的函數也能 Compile。覺得 UpdateLift 太難，可以先把 StartMove、OnArrived 這兩個簡單的做完。四個都寫好後，按 Play 才看得到電梯動。

UpdateLift 詳細做法（關卡 1）

關卡 1 的 UpdateLift 只處理「移動中」這一種狀態，約 20 個節點。先看懂邏輯，再照下面的表放節點、接線。

如果 State 不是 4 → 什麼都不做
如果 State 是 4（移動中）：
    Z      = 車廂目前高度                 （Kit Get Lift Z）
    Target = 目標樓層的高度               （FloorHeights[TargetFloor − 1]）
    Step   = 這一幀可以走的距離           （MoveSpeed × Get World Delta Seconds）
    如果 |Target − Z| ≤ Step  → 到了：車廂設到 Target，呼叫 OnArrived
    否則如果 Target > Z      → 往上：車廂設到 Z + Step
    否則                     → 往下：車廂設到 Z − Step

白線上的節點（依序執行）

圖中節點做什麼怎麼放
①Branch，Condition 接 State == 4是不是移動中右鍵搜尋 Branch，或按住 B 點左鍵
②Kit Get Lift Z取得目前高度 Z右鍵搜尋 Kit Get Lift Z
③Branch，Condition 接 Abs(Target − Z) <= Step到了沒同 ①
④Kit Set Lift Z（Z 接 Target）→ On Arrived到了：對齊目標、通知到站右鍵搜尋 Kit Set Lift Z；On Arrived 從 My Blueprint 拖進來
⑤Branch，Condition 接 Target > Z；True → Kit Set Lift Z（Z + Step），False → Kit Set Lift Z（Z − Step）還沒到：往上或往下移一步Kit Set Lift Z 可以用 Ctrl+C／Ctrl+V 複製
 
[UpdateLift] ▷ → [① Branch：State == 4]
                    True ▷ → [② Kit Get Lift Z] ▷ → [③ Branch：Abs(Target − Z) <= Step]
                                                     True  ▷ → [④ Kit Set Lift Z = Target] ▷ → [On Arrived]
                                                     False ▷ → [⑤ Branch：Target > Z]
                                                                 True  ▷ → [Kit Set Lift Z = Z + Step]
                                                                 False ▷ → [Kit Set Lift Z = Z − Step]
                    False → （不接）

計算數值的節點（沒有白線）

要算的值節點怎麼放
State == 4Get State → ==，下面的格子填 4Ctrl 拖 State；從它的輸出拉線，搜尋 ==
TargetGet FloorHeights → Get (a copy)；索引接 Get TargetFloor − 1Ctrl 拖 FloorHeights，從輸出拉線搜尋 Get (a copy)；Ctrl 拖 TargetFloor，拉線搜尋 -，下面填 1
StepGet MoveSpeed × Get World Delta SecondsCtrl 拖 MoveSpeed，拉線搜尋 *；右鍵搜尋 Get World Delta Seconds 接到下面
剩下的距離Target − Z → Abs從 Target 拉線搜尋 -，下面接 Z；再拉線搜尋 Abs
到了沒剩下的距離 <= Step從 Abs 拉線搜尋 <=，下面接 Step，輸出接 ③ 的 Condition
往上嗎Target > Z從 Target 拉線搜尋 >，下面接 Z，輸出接 ⑤ 的 Condition
Z + Step、Z − Step+、−從 Z 拉線搜尋 +、-，下面接 Step，輸出接兩個 Kit Set Lift Z 的 Z
四個容易錯的地方① Kit Get Lift Z 要接在白線上，而且在 ③ 前面：Z 是它執行後才有的值。② 索引要用 TargetFloor − 1：2F 是索引 1，忘了減會出現陣列越界。③ ③ 要用 <=，不要用 ==：高度是小數，幾乎不會剛好等於 500，用 == 會衝過頭。④ 同一個輸出可以接很多條線：Z、Target、Step 各只要一份，從同一個接腳拉多條線就好。
提示（卡住再打開）

目標高度可以用 Get (a copy) 從 FloorHeights 取出，索引要用 Floor − 1。

每一幀的移動量 = MoveSpeed × Get World Delta Seconds。

不要只判斷「目前高度 == 目標高度」。小數幾乎不會剛好相等，電梯會衝過頭。改成判斷「剩下的距離是不是已經小於等於這一步」，是的話直接把高度設成目標再呼叫 OnArrived。

驗收

  • 進車廂按 2，電梯上到 2F 並停住，玩家跟著上去
  • 按 1 回到 1F
  • 停下的位置剛好在樓板高度，不會抖、不會衝過頭

這就是「門沒關好之前電梯不能動」的做法：CallElevator 只負責把目的地記在 TargetFloor，只有待命（門已經全關）時才會呼叫 Start Move 出發，所以不用在 StartMove 裡檢查門。

容易錯的地方① Switch on Int 的出口不夠：要按 Add pin 加到 4。② OnArrived 忘了把 DoorAlpha 設成 0，門會從上一次的位置開始動。③ Kit Apply Doors 要接在白線上，否則門不會動。④ 開門、關門的比較要用 >= 1、<= 0，不要用 ==。⑤ 門開了就不關：檢查出口 1 的 ⑤ 有沒有把 DwellRemaining 設成 DwellTime。⑥ 按了別層沒反應：檢查 CallElevator 的 ⑦ 和 UpdateLift 出口 0。

C. 練習：自己新增 FindRequest 函數

Dispatch 需要知道「現在哪一層有人在等」。請把這個判斷寫成一個獨立的函數 FindRequest，再讓 Dispatch 呼叫它。這是整份作業裡唯一要你從零新增的函數，順便練習「有回傳值的函數」。

函數規格

項目內容
名稱FindRequest
輸入無
輸出Result（Integer）
要做的事從 1F 開始檢查 Requests，回傳第一個有人在等的樓層號碼（1 或 2）；都沒有人在等就回傳 0

建立步驟

  1. 在 My Blueprint 的 FUNCTIONS 那一列按右邊的 ⊕，新增一個函數。
  2. 把名稱改成 FindRequest，按 Enter。
  3. 在 Details 的 Outputs 按 ⊕，名稱改成 Result，型別選 Integer。圖表裡會自動出現一個 Return Node。
  4. 在入口節點和 Return Node 之間寫判斷。每一條路最後都要接到 Return Node，並把 Result 接上要回傳的值。
  5. Compile。之後在 Dispatch 裡就能放 Find Request 節點，它的 Result 輸出就是答案。

示意：輸入什麼、回傳什麼

Requests[0]（1F）Requests[1]（2F）FindRequest 回傳
falsefalse0（沒有人在等）
truefalse1
falsetrue2
truetrue1（從 1F 開始找，先找到的先回傳）
Dispatch 與 FindRequest 的關係（示意） Dispatch ──呼叫──▶ FindRequest ──回傳 Result──▶ Dispatch │ └─ 讀 Requests[0]、Requests[1] Dispatch 拿到 Result 之後： Result = 0 → 沒有人在等，什麼都不做 Result = 1 或 2 → 往那一層出發

             True  ▷ → ② Set Array Elem（Index ← CurrentFloor − 1，Item 不打勾）
                     ▷ → ③ Kit Set Button Light（Floor ← CurrentFloor，On 不打勾）▷ → ④ Set State = 1
             False ▷ → ⑤ Find Request ▷ → ⑥ Branch（Result > 0） True ▷ → ⑦ Start Move（Floor ← Result）

為什麼先檢查本層：如果本層有登記卻直接交給 FindRequest，它可能回傳本層，電梯就會對自己 Start Move、原地「移動」一次才開門。先檢查本層，直接開門比較乾淨。

F、G. 擋門

Kit Is Door Blocked 在問什麼輸入 Floor，回傳 Blocked（Boolean）：玩家是不是站在第 Floor 層的門口（門外大約 1～2.3 公尺、左右 1 公尺內、同一層）。它是查詢用的 Kit 節點，但一樣有白色 ▷，要串在白線上，Blocked 才會是這一幀的結果。Floor 一律接 Get CurrentFloor。

只需要在兩個狀態檢查：停留快結束時（出口 2）和門正在關的時候（出口 3）。開門中、全開停留中，門本來就不會夾到人，不用檢查。

F. UpdateLift 出口 2：停留時間到了，門口有人就再等

邏輯：倒數 → 數完了 → 門口有人？ 有：再等 0.5 秒　沒有：開始關門
S 的 2 ▷ → ① Set DwellRemaining ← DwellRemaining − Δt
         ▷ → ② Branch（DwellRemaining <= 0）
               True ▷ → ③ Kit Is Door Blocked（Floor ← CurrentFloor）
                       ▷ → ④ Branch（Blocked）
                             True  ▷ → ⑤ Set DwellRemaining = 0.5
                             False ▷ → ⑥ Set State = 3

G. UpdateLift 出口 3：門正在關，門口有人就重新打開

邏輯：先問門口有沒有人 → 有：切回開門　沒有：照關卡 2 繼續關門
S 的 3 ▷ → ① Kit Is Door Blocked（Floor ← CurrentFloor）
         ▷ → ② Branch（Blocked）
               True  ▷ → ③ Set State = 1
               False ▷ → ④ Set DoorAlpha ← Max( DoorAlpha − Δt ÷ DoorOpenTime , 0 )
                       ▷ → ⑤ Kit Apply Doors ▷ → ⑥ Branch（DoorAlpha <= 0） True ▷ → ⑦ Set State = 0

為什麼 ③ 只要 Set State = 1、不用改 DoorAlpha：DoorAlpha 停在關到一半的值，下一幀出口 1 會從這個值繼續 +，門就從目前的位置順順地打開，不會跳回全關。

容易錯的地方① Index 忘了減 1：按 1 會登記成 2F，按 2 寫到不存在的第 2 格（Output Log 出現陣列越界的警告）。② OnArrived 沒清掉登記：到站開門、關門之後，Dispatch 發現本層還有登記，門又再開一次。③ CallElevator 還留著 Branch（State != 4）：移動中按的還是被忽略。④ 出口 0 忘了換成 Dispatch：Requests 有登記但電梯不會動。⑤ Kit Is Door Blocked 沒接白線：Blocked 永遠是 false，擋門沒效果。⑥ FindRequest 有一條路沒接 Return Node：那條路會回傳預設的 0。

驗收

  • 在車廂按 2，電梯往上時再按 1：1 號燈亮著，到 2F 開門、停留、關門後，自動回 1F
  • 電梯在 2F 停留時，到 1F 門外按 E：2F 關好門才下來
  • 停留時間到了但你站在門口：門不關，離開門口後約 0.5 秒開始關
  • 門正在關時走進門口：門重新打開
  • 沒有人按任何按鈕時：電梯停在原地，門關著不動

挑戰（選做）

把出口 4 的等速移動改成先加速、再減速：多一個變數記目前速度，每一幀加一點，快到站時減一點。

13測試與除錯

每次修改後的固定流程

  1. 按 Compile。下方 Compiler Results 出現紅字就點它，會跳到出錯的節點。
  2. 按 Ctrl+S 存檔。
  3. 回到主視窗按 ▶ Play，在練習地圖裡實際走一次。

測試時的按鍵

按鍵位置會呼叫
E某層電梯門外約 2.5 m 內OnCallButtonPressed(該層)
1 / 2車廂裡OnCabinButtonPressed(1 或 2)

不在車廂裡按 1／2，畫面會顯示「EV: 請先進入電梯，或到門外按 CALL [E]」，這是正常的。

除錯技巧

  • Print String：狀態改變時印出來，例如「State 1 → 2」。用 Append 把文字和數字接在一起。
  • 即時看執行路線：Play 時切到 BP 編輯器，工具列的 debug 下拉選單選 EV，正在執行的白線會發光。
  • 中斷點：選一個節點按 F9，執行到那裡會暫停，滑鼠移到接腳上可以看當時的值。再按 F9 取消。

14寫好之後，搬到自己的場景

程式全部在 BP_ElevatorKit 裡，只要搬這個 BP。

同一個專案的另一張地圖

  1. 打開你的地圖。
  2. 從 Content Browser 把 BP_ElevatorKit 拖進關卡。

另一個專案

  1. 在 Content Browser 對 BP_ElevatorKit 按右鍵 → Asset Actions → Migrate…
  2. 清單會自動勾好它用到的材質，按 OK。
  3. 目的地選對方專案的 Content 資料夾。

擺放規則

  • Rotation 保持 0。電梯門朝 −X 方向，玩家要站在電梯的 −X 側。
  • 高度：電梯 actor 的 Z = 1F 地板頂面 − 50。例如地板頂面是 10，就放在 Z = −40。
  • 樓板要開孔：2F 樓板在電梯位置要留約 3.2 m 的孔，車廂才上得去。
  • 層高 500 cm。如果你的房子層高不同，請找老師。

15常見問題

可以修改 Kit_ 函數嗎？

不行。Kit 函數是給你用的工具，改了之後其他功能可能壞掉。如果覺得 Kit 函數有問題，先找老師。

按了 Compile 還要存檔嗎？

要。Compile 只是檢查並套用，Ctrl+S 才會寫進檔案。關閉 Unreal 前，右下角要顯示 All Saved。

不小心把 EventGraph 的接線拉斷了

先按 Ctrl+Z 復原。如果已經存檔了，對照第 5 節的截圖把線接回去。
