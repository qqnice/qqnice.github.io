④ 動手做實驗：先預測、再用「🔬 單步一幀」驗證

點擊任一情境會自動擺好現場並暫停，讓你用「單步執行」一格一格看清楚狀態機怎麼思考。

實驗 01 · 排隊與派車

門開著時，收到 2F 呼叫會立刻衝出去嗎？

1F 門全開（State 2）時按下 2F。觀察 Requests[1] 已經變成 true，但為什麼電梯還停在原地？

實驗 02 · 防夾優先權

門關到一半（40%），突然有人站到門口！

在 State 3 (關門中) 把人放到門口。點一下單步：會先繼續關門，還是立刻切回 State 1？門開度會歸零嗎？

實驗 03 · 移動中不掉頭

正往 2F 上樓途中，1F 又有人按按鈕！

電梯在 State 4 升到 200cm 時收到 1F 請求。它會半路折返，還是先完成 2F 的開關門才下樓？

🐞 藍圖除錯診所：如果接錯線會發生什麼災難？

初學者在 Unreal 接線時最常犯這 3 個錯誤。點一下親眼看看「沒有照狀態機規則寫」會出現什麼好笑又危險的 Bug！

常見 Bug A · 敞開大門飛天

在 CallElevator 直接呼叫 StartMove

如果不先登記到 Requests 等待命才派車，而是按下按鈕就直接 Set State = 4，門還沒關就會直接帶著人飛上樓！

常見 Bug B · 無限開關門鬼打牆

OnArrived 忘記清除 Requests 陣列

到達樓層時如果忘了把該層的 Requests 設回 false，電梯關好門回到 State 0 又會以為有人叫，永遠困在同一層！

常見 Bug C · 瞬間秒關夾人門

把 DoorAlpha 直接設成 0 而不是每幀遞減

在 UpdateLift 如果忘了用 DoorAlpha - dt / DoorOpenTime，而是直接 Set DoorAlpha = 0，門會在 1 幀內瞬間夾死！
